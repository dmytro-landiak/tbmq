<objective>
Implement Netty TCP server bootstrap with Epoll/NIO detection, connection counting with configurable limits, Caffeine cache configuration, and Prometheus metrics exposure.

Purpose: This plan delivers the network layer (TCP accept on port 1883), the in-process cache (Caffeine replacing Redis), and the observability stack (Prometheus metrics). Together with Plan 01's storage layer, this makes the broker a running process that accepts connections and exposes metrics.

Output: A Spring Boot application that starts, opens RocksDB, binds Netty on port 1883, exposes `/actuator/prometheus` with JVM and custom metrics, and shuts down gracefully in the correct order (Netty first, then RocksDB).
</objective>

    `start()`:
    1. Detect Epoll: `boolean epollAvailable = Epoll.isAvailable()`
    2. Create bossGroup: `epollAvailable ? new EpollEventLoopGroup(config.getBossThreads()) : new NioEventLoopGroup(config.getBossThreads())`
    3. Create workerGroup: same pattern, thread count = `config.getWorkerThreads() > 0 ? config.getWorkerThreads() : Runtime.getRuntime().availableProcessors()`
    4. Channel class: `epollAvailable ? EpollServerSocketChannel.class : NioServerSocketChannel.class`

    6. `serverChannel = bootstrap.bind(config.getPort()).sync().channel()`
    7. `running = true`
    8. Log: `"MQTT TCP listener started on port {} (transport: {})", config.getPort(), epollAvailable ? "epoll" : "nio"`

    1. Close serverChannel: `if (serverChannel != null) serverChannel.close().awaitUninterruptibly()`
    2. Shutdown bossGroup: `bossGroup.shutdownGracefully(0, 5, TimeUnit.SECONDS).awaitUninterruptibly()`
    3. Shutdown workerGroup: same pattern
    4. `running = false`
    5. Log: `"MQTT TCP listener stopped"`

    - `@Configuration`, `@EnableCaching`, `@RequiredArgsConstructor`, `@Slf4j`
    - Injected: `MeterRegistry meterRegistry`
    - `@Bean CaffeineCacheManager caffeineCacheManager()`:
      1. Create `CaffeineCacheManager`
      2. Set default Caffeine spec: `Caffeine.newBuilder().maximumSize(10_000).expireAfterWrite(Duration.ofMinutes(5)).recordStats()`
      3. Return the cache manager
    - `@Bean MeterBinder caffeineCacheMetrics(CaffeineCacheManager cacheManager)`:
      Returns a `MeterBinder` that registers cache metrics. Use `CacheMetricsRegistrar` or manual binding per Micrometer docs. The simplest approach: override `caffeineCacheManager()` to create caches that are individually registered. Alternative: use a `@PostConstruct` that iterates cache names and binds them.

      Actually, the cleanest approach for Phase 1: Spring Boot auto-configures Caffeine cache metrics when `spring.cache.type=caffeine` is set and Actuator is on the classpath. The `management.metrics.enable.cache=true` (default) auto-registers cache metrics. So the `CacheConfiguration` mainly needs to:
      1. Define the `CaffeineCacheManager` bean with `recordStats()` enabled (required for metrics)
      2. Pre-register expected cache names: `"credentials"`, `"acl_rules"`, `"sessions"` (Phase 2+ will use these)
      3. Spring Boot Actuator auto-binds Caffeine caches with `recordStats()` to Micrometer

    ```java
    @Configuration
    @EnableCaching
    @Slf4j
    public class CacheConfiguration {

        @Bean
        public CaffeineCacheManager cacheManager() {
            CaffeineCacheManager manager = new CaffeineCacheManager();
            manager.setCaffeine(Caffeine.newBuilder()
                .maximumSize(10_000)
                .expireAfterWrite(Duration.ofMinutes(5))
                .recordStats());
            // Pre-register caches for Phase 2+ consumers
            manager.setCacheNames(List.of("credentials", "acl_rules", "sessions"));
            log.info("Caffeine cache manager initialized with caches: credentials, acl_rules, sessions");
            return manager;
        }
    }
    ```
