<objective>
Wire the dispatch service, trie-backed subscription registry, and trie-backed retained message service into the broker, refactoring ClientActor to route all publishes through the bounded dispatch queue.

Purpose: This plan implements the core Phase 3 transformation: publisher actors no longer iterate subscribers inline. Instead, they call `MsgDispatcherService.dispatch()` which enqueues the message. Background consumer threads perform wildcard trie lookup and send `DeliverMsg` to subscriber actors. This ensures Netty I/O threads are never blocked by delivery fan-out (INFR-01) and the queue implementation is swappable via factory interface (INFR-04).

Output: Working dispatch pipeline — publish goes through queue, consumer threads match wildcards via trie, and deliver via actor mailbox. Retained message service uses trie for wildcard delivery on subscribe.
</objective>
